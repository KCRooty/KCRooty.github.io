Static Linux

La distribución Linux propia de Static Forge. Base Arch Linux, detección automática de hardware con sl-detect, entornos que se adaptan a la máquina y perfiles de privacidad configurables desde la instalación. Sin telemetría. Sin relleno.

01 · el proyecto

Arquitectura

Static Linux no es un remaster estático de Arch con un wallpaper distinto: cada instalación se adapta al hardware real de la máquina, desde un netbook de 2013 hasta un equipo moderno con GPU dedicada.

Base

Construida sobre Arch Linux con archiso. Rolling release, paquetería de Arch al completo. Dos perfiles de ISO en el repo: profiledir-online (~1 GB, se actualiza cada mes) y profiledir-offline (~4 GB, cada trimestre).

Entornos adaptativos

Hyprland + Astal (full o lite, Wayland) en equipos con RAM suficiente, XFCE tematizado (Xorg) cuando el hardware no soporta Wayland o anda justo de RAM, y Openbox minimal para máquinas de 512 MB. Lo decide sl-detect, no el usuario a mano.

Sistema de archivos

BTRFS por defecto en SSD con ≥4 GB de RAM (snapshots vía Snapper), ext4 como opción segura, F2FS en almacenamiento eMMC. XFS también soportado. ZFS está en el roadmap.

Privacidad

Tres perfiles seleccionables en el instalador — Básico, Mejorado y Máximo — cada uno con su propio kernel y su propia capa de herramientas. Ver la sección Privacidad más abajo.

02 · sl-detect

Detección automática de hardware

Antes de que aparezca la interfaz de Calamares, sl-detect ya sabe qué máquina tiene delante. Es Python puro de librería estándar (corre en la ISO live mínima, como root, sin dependencias) y nunca falla: cualquier sonda que no puede completarse cae a un fallback seguro — XFCE, ext4, kernel LTS.

$ sl-detect --all
$ sl-detect --json              # consumido por el módulo de Calamares
$ sl-detect --recommend-env     -> hyprland-astal-full | ...-lite | xfce-themed | openbox-minimal
$ sl-detect --recommend-fs      -> btrfs | ext4 | f2fs
$ sl-detect --recommend-kernel  -> linux-lts | linux-zen
$ sl-detect --gpu               # modelo, driver, soporte Wayland

Ejemplo real — el primer equipo de pruebas del proyecto, un Packard Bell iMedia S2883 (Celeron J1900, Bay Trail, 3.64 GB usables, HDD de 250 GB, UEFI): 
→ entorno   : xfce-themed      (Bay Trail = sin Wayland, forzado)
→ fs        : ext4             (HDD)
→ kernel    : linux-lts        (HDD + CPU de 2013)
→ I/O sched : bfq
swapfile 2G : true              (RAM < 4 GB — necesario para compilar con paru/Rust)

El conocimiento de hardware vive en archivos .rules (GPU, Wayland, entorno, kernel) — añadir una GPU nueva no toca una línea de código Python. 28 tests unitarios sin dependencias externas cubren la lógica.

03 · arranque

Bootloader y gestión de memoria

Hoy el instalador configura GRUB con efibootmgr y os-prober (detecta otros sistemas operativos al instalar). Con BTRFS, grub-btrfs añade automáticamente los snapshots de Snapper como entradas de arranque — puedes arrancar directamente una foto del sistema anterior a un tweak que salió mal.

Arranque actual

grub + efibootmgr + os-prober + grub-btrfs. UEFI y BIOS. Fallback a BOOTX64.EFI en UEFI limitado (validado en el Packard Bell de pruebas).

En el roadmap

El diseño del proyecto contempla también systemd-boot, Limine y rEFInd como alternativas — todavía no hay módulo de Calamares para elegir entre ellos; por ahora es GRUB para todos.

Memoria

zram-generator + earlyoom de fábrica: swap comprimida en RAM y el proceso que más memoria consume se mata antes de que el sistema se congele.

Kernel según hardware

linux-lts por defecto (o si hay HDD / CPU anterior a 2015), linux-zen en los perfiles de privacidad Básico y Mejorado, linux-hardened en el perfil Máximo.

04 · privacidad

Tres perfiles, un interruptor

Desde cero, cada instalación ya lleva ufw, dnscrypt-proxy y apparmor. Los tres perfiles añaden capas por encima — y cada acción que tocan es reversible con backup automático, sin excepciones.

PerfilKernelAñade sobre el baseline
Básicolinux-zenBaseline (ufw, dnscrypt-proxy, apparmor) — nada más encima.
Mejoradolinux-zen+ firejail (sandboxing) · usbguard · bleachbit + mat2 (limpieza de metadatos)
Máximolinux-hardened+ todo lo anterior + proxy tor/torsocks/proxychains-ng · swap cifrada (cryptsetup) · MAC randomization agresiva · kloak (ofuscación del timing de teclado, paquete AUR)
Se elige durante la instalación con el módulo privacidad de Calamares, y se puede cambiar después con sl-ctl privacy.

Branding propio

Sistema de acentos

Un único selector recolorea todo el sistema — fastfetch, GTK 3/4, el borde de ventana de xfwm4, xfce4-terminal, el greeter de LightDM y el fondo de pantalla — a partir de palette.conf. Morado es el acento por defecto.

os-release & fastfetch

/etc/os-release propio (NAME="Static Linux", ID_LIKE=arch, color ANSI = Signal Green) y un fastfetch minimalista de fábrica con el logo de Static Forge — el sello del estudio desde el primer arranque de terminal.

XFCE tematizado

Adwaita-dark + Papirus-Dark, tipografías Space Grotesk / JetBrains Mono, tema de ventana Static-Void, panel único con Whisker, tiling con Super+flechas y greeter de LightDM con la marca del estudio.

08 · estado del proyecto

Qué hay hecho, qué falta

Ya funciona

  • sl-detect (hardware, 28 tests)
  • 3 perfiles de privacidad
  • Sistema de acentos (10 colores)
  • Entorno XFCE tematizado
  • os-release / fastfetch propios
  • Módulos base de Calamares

En camino

  • sl-welcome (app GTK4 de bienvenida)
  • Sabores / presets de instalación
  • Entornos Hyprland+Astal y Openbox
  • Build de ISO automatizado
  • systemd-boot / Limine / rEFInd
  • Primera ISO pública firmada
Todavía no hay una ISO pública para descargar. Los perfiles de archiso (online / offline) están en el repo pero el script de build se está terminando de automatizar. Sigue el progreso real, commit a commit, en GitHub.
09 · comunidad

Contribuir

Es un proyecto de Static Forge, licenciado GPL-3.0. Toda contribución debe ser compatible con esa licencia, y para cambios grandes se abre un issue antes de tocar código.

Dónde hace falta ayuda

Reglas de GPU para hardware raro y placas ARM · integración de sabores y perfiles en Calamares · desarrollo de sl-welcome (GTK4) · wallpapers y tema de SDDM/Plymouth · testing en hardware variado, sobre todo equipos antiguos · port a ARM64 (RPi 4/5, Pinebook Pro, RK3588).

Reportar un bug

Plantillas de bug report y de hardware report en GitHub Issues. Incluye siempre la salida de sl-detect --all, el modelo de hardware y qué ISO (online/offline) estabas usando.

Commits convencionales (feat:, fix:, docs:...) y cada tweak de sl-ctl o acción de privacidad con backup/restore automático — ningún cambio irreversible, nunca.
