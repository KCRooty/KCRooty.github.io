01 · el proyecto

¿Qué es Static Linux?

Base

Construida sobre Arch Linux con archiso. Rolling release, paquetería de Arch al completo, sin capas innecesarias entre el sistema y el usuario.

Escritorio

XFCE tematizado como entorno principal, ligero y estable. Explorando también un entorno Hyprland para quien prefiera un flujo en mosaico.

Instalador

Calamares, el instalador gráfico estándar de las distros basadas en Arch. Particionado guiado, sin fricción, listo en minutos.

Filosofía

Privacidad por defecto: sin telemetría ni servicios de terceros metidos con calzador. fast. private. yours.

02 · herramientas propias

sl-ctl & sl-detect

Static Linux no es solo una capa visual sobre Arch: trae herramientas propias de Static Forge integradas en el sistema.

sl-detect

Detección de hardware con reglas propias y su propia batería de tests. Identifica el equipo en el arranque para aplicar la configuración correcta sin intervención manual.

sl-ctl

Utilidad de control y configuración del sistema, pensada para gestionar Static Linux desde línea de comandos con las convenciones del propio Static Forge.

03 · identidad visual

Branding propio

Sistema de acentos

Sistema de color de acento "whole-look" con 10 acentos distintos, para que cada instalación se pueda personalizar manteniendo la coherencia visual de Static Forge en cada rincón del sistema.

Incluye además un os-release propio y un fastfetch minimalista de fábrica — el sello de Static Forge desde el primer neofetch.

05 · documentación

Wiki

Lo esencial de cada pieza, en el mismo sitio. Para el detalle completo (reglas de sl-detect, listas de paquetes, PKGBUILD...) está el wiki fuente en GitHub.

El instalador gráfico (Calamares) todavía está en desarrollo — la vía probada hoy es la manual, la misma con la que se validó Static Linux en el iMedia S2883.

1 · Live + partición

Arranca el live de Arch, particiona EFI + raíz. sl-detect recomienda EXT4 en HDD, BTRFS en SSD con ≥4 GB.

2 · Base

pacstrap con packages/lists/base.list, GRUB con fallback a BOOTX64.EFI para firmwares UEFI limitados.

3 · Entorno

Instala el paquete del entorno elegido y corre su install.sh --home — dotfiles, tema y acento de una vez.

Validado en un Packard Bell iMedia S2883 (Celeron J1900, 2013, rescatado de la basura): 3.64 GB usables, GPU Bay Trail sin Wayland viable → sl-detect recomendó XFCE + EXT4 + linux-lts, tal cual.

XFCE temático

≥1 GB, Xorg. El único entorno validado en hardware real hasta ahora.

Openbox minimal

512 MB, Xorg. Sin compositor por defecto — cero MB de más en reposo.

Hyprland + Astal (lite)

2-4 GB, Wayland. Shell propio en Astal/AGS, sin blur ni sombras.

Hyprland + Astal (full)

≥4 GB, Wayland. Mismo shell, blur y animaciones completas.

Básico

Defaults de día 0 + UFW + aleatorización de MAC. Kernel linux-zen.

Mejorado

+ Firejail + AppArmor + USBGuard. Kernel linux-zen.

Máximo

+ Tor + kloak + swap cifrado. Kernel linux-hardened.

Los tres con backup/restore automático antes de tocar nada — reversibles siempre, sin excepción.

¿Por qué Arch?

Base rodante, AUR para todo, y es sobre lo que ya está construido sl-detect. Decisión cerrada.

¿Secure Boot?

No soportado. GRUB sin firmar + Secure Boot puede dejar el sistema sin arrancar — el instalador avisa si lo detecta.

¿Por qué el techo son 4 GB?

Porque el hardware que este proyecto quiere revivir vive ahí o por debajo — no es un límite duro, es dónde se prueba primero.

¿Cero telemetría de verdad?

Sí, en los tres perfiles. No es un perfil — es la línea base.
